六组 BehaviorSpace 实验

情景种子 2026–2055 对应地图种子 1–30，实验 setup 用 set map-seed scenario-seed - 2025 配对。参数组合本身枚举了 30 个情景，因此 repetitions=1 不等于只做一个随机情景。每场 500 cycle，记录终点指标。

六组都固定人口 5×10、需求 30–50、随机时长 1–10、指定故障关闭。未变化的参数采用容量基准 100、目标倍数 1、运费 3、价格反馈 0.20、维护费 50、持有费 1。初始库存仍抽取 40–80，修改目标不会额外发放库存。界面暂时改人数不会改变保存的实验设置。

新增四组的 setup 为什么多几行：initialize-scenario 会 clear-all 并重置经济参数。setup 先用局部变量保存目标、价格反馈和费用，初始化后恢复，再把制造商的目标设为 demand × 倍数。目标赋值放在 with-local-randomness 中，不干扰模型随机流。运费直接作为初始化参数传入，确保在初始选商之前生效。

六组全跑共 4,590 场，其中前五组共 2,160 条记录，去掉跨组重叠后是 1,530 个不同参数／种子组合。原风险与运费两组仍共享 90 场基准，两者去重后为 450 场。不能把重叠基准或不同费用下的同一物理轨迹当成独立重复样本。

跨函数追一遍：一个值是怎么走完系统的

库存从上一期走到下一期

inventory（上期结余）
→ place-orders：inventory-at-start = inventory；Q = D + T − inventory
→ deliver-orders：每条合同产生 units-delivered
→ update-manufacturer-results：amount-received = Σ units-delivered
→ available = inventory-at-start + amount-received
→ production-met = min(demand, available)
→ inventory = available − production-met
→ 下一期 place-orders 再读这个 inventory

本期的报价不会被本期订单反向修改

record-supplier-results（t−1）：capacity-utilization
→ update-supplier-prices（t）：pricing-utilization → unit-price
→ 合同 landed-unit-cost → place-orders 的倒数成本份额
→ allocate-supply → deliver-orders
→ record-supplier-results（t）：写新 capacity-utilization
→ update-supplier-prices（t+1）：才形成下一期报价

为什么清零位置不同？

place-orders 先把每条合同的订单和份额清零，因为没获得新订单的合同也必须归零。其他本期结果在后续过程里对全体对象覆盖重算，例如 deliver-orders 总会重新写每条合同的交货和费用；累计量则只能做加法，不能每期归零。

没有写在代码里的机制，不能在 viva 中声称存在

没有根据拥堵重新优化供应商组合、没有自动换伙伴、没有运输在途时间、没有需求季节性、没有供应商因收入再投资、没有区域相关故障、没有机器学习或均衡求解。订单倒数成本权重与上一期利用率加价是明确的行为规则；反馈可产生复杂结果，但不是最优策略求解器。

代码追问练习

考官指着 [order-quantity] of end1：为什么不能直接写 order-quantity？
这里已经进入 ask eligible，即合同上下文。order-quantity 属于制造商，因此要显式读取合同起点 end1。
为什么 create-contract-to 的方向与货物运输方向相反？
连线代表采购/下单关系：制造商指向供应商；交货由合同记录数值，方向不会自动决定运输。
为什么先设 transport-cost-per-distance 再 create-network？
初始伙伴排序已经依赖运费。先选商再改运费会把一个运费条件下的合同网络错误地用到另一个条件。
为什么 update-supplier-prices 放在 record-supplier-results 前？
它必须读取上一期利用率。本期发货在后面记录，用于下一期报价，避免同一期循环依赖。
settings-snapshot 为什么有用？
一方面防止 clear-all 丢掉待用的内部设置，另一方面确保 go 期间界面参数未改变。
with-local-randomness 与固定 seed 是同一个作用吗？
固定 seed 使某段抽样可复现；局部随机流让这段抽样不污染外围随机状态。再通过每个供应商/周期的专用 seed，使外部故障不随采购策略变化。
为什么故障时 fill-ratio=0，但正常零订单时 fill-ratio=1？
两者都产生零交付，但含义不同：前者完全不可供货，后者没有配给短缺且避免除零。
unit-price 和 landed-unit-cost 有何区别？
前者只有供应商采购报价，后者加上合同路线的每单位运费；固定合同费、库存费均不在其中。
为什么统计 reporter 返回 false，不返回 0？
在需求或满足量为 0 时比率未定义。返回 false 标记缺失，比返回一个可误解为真实结果的 0 更明确。界面包装再转 N/A。
如果要加入“第二轮紧急采购”，从哪里改，为什么不是一行？
必须在新故障之后设计剩余订单、剩余产能、第二轮分配和计费规则，并明确是否重复交货；不能直接再调用 place-orders，因为它会清零和覆盖第一次的订单。这里只解释改动边界，当前模型没有这个机制。
